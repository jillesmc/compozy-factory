# ADR-002: Project values only in factory.toml; New Relic defaults per workspace

## Status

Accepted

## Date

2026-11-17

## Context

A global agent definition has one AGENT.md and one HEARTBEAT.md for all projects. Today the prompts and
the sentinel's HEARTBEAT carry project values (repo, branches, Jira prefix, runner rule, New Relic account
`1234567` and app `acme-portal-production`). `compozy-newrelic` requires `with.account_id` in each source
(`src/params.ts`). Operator decision Q21 = a.

## Decision

- Every project value moves to `<project>/.compozy/factory/factory.toml`; prompts and source scripts read
  it from the workspace root; a missing key makes the agent refuse (BR-4).
- `compozy-newrelic` accepts optional per-workspace `NEW_RELIC_ACCOUNT_ID` (default account) and
  `NEW_RELIC_APP` (expands `{{app}}` in `with.where`, quotes rejected). An explicit `with.account_id`
  still wins, so existing users are unaffected (additive public-surface change).

## Alternatives Considered

### Alternative 1: Keep the sentinel project-local

- **Description**: all agents global except the sentinel.
- **Pros**: no extension change.
- **Cons**: an exception to the model; each project copies the sentinel.
- **Why rejected**: operator chose uniformity (Q21 = a).

### Alternative 2: Script source instead of extension kinds

- **Description**: a sentinel script that reads `factory.toml` and queries New Relic.
- **Pros**: no extension change.
- **Cons**: duplicates the extension's NerdGraph client and credential handling.
- **Why rejected**: more code, weaker isolation.

## Consequences

### Positive

- Attaching a project needs only `factory.toml` and two workspace values.

### Negative

- Two places hold New Relic app identity (`factory.toml` for prompts, `NEW_RELIC_APP` for sources).

### Risks

- NRQL injection through `NEW_RELIC_APP`. Mitigation: quotes rejected (UT-045).

## Implementation Notes

`factory.toml` key renames (BR-6) ship in the cutover commit; agents read only new keys.
